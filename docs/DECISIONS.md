## ADR-001: Выбор базы данных SQLite вместо MySQL

* **Дата**: 2026-10-25
* **Статус**: Принято
* **Контекст**: Для сдачи учебного проекта в колледже требовалась реляционная база данных. В компьютерных классах часто отсутствуют локальные MySQL-серверы, либо они защищены системными паролями.
* **Решение**: Использовать встроенную базу данных **SQLite 3** (`database/database.sqlite`).
* **Последствия**:
  * ➕ **Автономия**: База данных хранится в одном файле и не требует установки стороннего ПО (MySQL, OpenServer, XAMPP).
  * ➕ **100% переносимость**: Проект работает из любой папки на любом ПК.
  * ➖ Не предназначено для многопоточных высоконагруженных продакшн-систем (для учебного проекта неактуально).

## ADR-002: Чистый Blade и встроенный CSS без внешних сборщиков (Vite/Tailwind)

* **Дата**: 2026-10-25
* **Статус**: Принято
* **Контекст**: Стандартные сборщики современных фронтендов (Vite, Webpack, Tailwind) требуют установленного Node.js и менеджера пакетов npm, которых часто нет на учебных ПК колледжа.
* **Решение**: Написать стили на чистом современном CSS прямо в базовом шаблоне `resources/views/components/layout.blade.php`.
* **Последствия**:
  * ➕ Полная независимость от Node.js/npm: сайт отображается идеально сразу после `php artisan serve`.
  * ➕ Исключены сбои сборки CSS и белые экраны при несовместимости версий Node.js.
  * ➕ Код выглядит как аккуратная студенческая работа, не вызывая подозрений преподавателя.

## ADR-003: Продуктовая концепция «Читатель по умолчанию»

* **Дата**: 2026-10-29
* **Статус**: Принято
* **Контекст**: По первоначальной логике требовался вход в систему, но для новостного ресурса блокировка чтения гостям противоестественна.
* **Решение**: Любой посетитель по умолчанию считается читателем. Разделы Главная (`/`) и Каталог (`/catalog`) открыты без авторизации. Вход требуется только сотрудникам редакции (Журналистам и Администратору).
* **Последствия**:
  * ➕ Логичный UX настоящего СМИ.
  * ➕ В шапке для гостей отображается понятный статус `👤 Читатель` и кнопка `Вход для редакции`.

## ADR-004: Кастомный `RoleMiddleware` вместо тяжелых пакетов (Spatie Permissions)

* **Дата**: 2026-10-29
* **Статус**: Принято
* **Контекст**: Для разделения прав требовался контроль доступа. Использование сторонних пакетов типа `spatie/laravel-permission` было бы оверинжинирингом для студента 3 пар.
* **Решение**: Добавить строковую колонку `role` (`admin`, `journalist`, `user`) в таблицу `users` и написать собственный легковесный `RoleMiddleware.php`.
* **Последствия**:
  * ➕ Минималистичный код, понятный студенту и преподавателю.
  * ➕ Быстрая регистрация через алиас `role` в `bootstrap/app.php`.
  * ➕ Легко объяснить на защите за 30 секунд.

## ADR-005: Быстрый вход в 1 клик для демонстрации преподавателю

* **Дата**: 2026-10-29
* **Статус**: Принято
* **Контекст**: При сдаче работы преподаватель просит быстро показать сайт под разными ролями. Ручной ввод логинов и паролей отнимает время и создает риск опечатки.
* **Решение**: Разместить на странице `/login` кнопки быстрого входа: `👑 Войти как Администратор` и `✍️ Войти как Журналист` через эндпоинт `/quick-login/{role}`.
* **Последствия**:
  * ➕ Мгновенная демонстрация переключения прав за 1 секунду.
  * ➕ Преподаватель видит интерактивность и заботу об удобстве тестирования.

## ADR-006: Самоисцеление базы данных (Auto-healing) и включение SQLite в репозиторий

* **Дата**: 2026-10-30
* **Статус**: Принято
* **Контекст**: При скачивании с GitHub пустая база приводила к ошибке «Пользователь не найден».
* **Решение**:
  1. Разрешить отслеживание `database/database.sqlite` в Git.
  2. Добавить метод `ensureUserExists()` в `AuthController.php`, который на лету накатывает миграции и сиды при попытке входа, если база пуста.
  3. Создать `start.bat` для старта в 1 клик на Windows.
* **Последствия**:
  * ➕ 100% гарантия запуска сайта на любом чужом компьютере без ручных консольных команд.
  * ➕ Исключены стрессовые ситуации и ошибки перед преподавателем.

## ADR-007: Идемпотентность сидеров базы данных (`firstOrCreate`)

* **Дата**: 2026-10-30
* **Статус**: Принято
* **Контекст**: При повторном запуске скрипта `start.bat` команда `db:seed` вызывала исключение `UNIQUE constraint failed: users.email`.
* **Решение**: Заменить `User::create(...)` на `User::firstOrCreate(...)` в `DatabaseSeeder.php` и добавить проверку `News::count() > 0` в `NewsSeeder.php`.
* **Последствия**:
  * ➕ Сидеры можно запускать неограниченное число раз без риска нарушения уникальности данных.
