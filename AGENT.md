## 2. Ключевые требования преподавателя (ТЗ)

1. **Шапка (`<x-header />`)**:
   - Находится сверху, зафиксирована (`sticky`), одинакова на всех страницах.
   - Меню строго из 4 разделов:
     - `Главная` (`/`) — общая лента всех новостей с цветными бейджами и фильтрацией по рубрикам.
     - `Каталог` (`/catalog`) — лента новостей с возможностью быстрого выбора темы.
     - `Журналист` (`/journalist`) — страница публикации новости (поля: «Заголовок», «Рубрика», «Текст статьи»).
     - `Администратор` (`/admin`) — панель модерации публикаций и управления пользователями.
2. **Подвал (`<x-footer />`)**:
   - Единый аккуратный футер внизу всех страниц.
3. **Карточки новостей (`<x-news-card />`)**:
   - Выводятся вертикальным списком.
   - Содержат: номер статьи (`№ ID`), бейдж рубрики, дату публикации, крупный заголовок и текст новости.

## 3. Логика ролей и авторизации

### Концепция «Читатель по умолчанию» (ВАЖНО!):
- **Каждый посетитель сайта — уже Читатель по умолчанию**. Ему открыты Главная и Каталог.
- Посетителю **НЕ нужно** регистрироваться или входить, чтобы читать новости.
- В шапке для гостей отображается бейдж `👤 Читатель` и кнопка `Вход для редакции`.
- Авторизация требуется **только для сотрудников**: Журналистов (создание новостей) и Администраторов (модерация).

### Таблица ролей (`users.role`):
| Роль | В коде | Доступные разделы | Описание |
|------|--------|-------------------|----------|
| **Читатель** | `user` (или гость) | `/`, `/catalog` | Просмотр новостей и фильтрация рубрик |
| **Журналист** | `journalist` | `/`, `/catalog`, `/journalist` | Создание и публикация статей |
| **Администратор** | `admin` | Все разделы, `/admin`, `/admin/news/{id}/edit` | Полный доступ: редактирование/удаление любых новостей, смена ролей пользователей |

### Ограничение доступа через Middleware:
- Защита маршрутов реализована через кастомный `app/Http/Middleware/RoleMiddleware.php`.
- Зарегистрирован алиас `'role'` в `bootstrap/app.php`.
- Неавторизованный гость при переходе на `/journalist` или `/admin` редиректится на `/login` с понятным уведомлением.
- Пользователь без прав получает стандартный `403 Forbidden`.

## 6. Базовые команды для работы

Все команды выполняются в папке: `C:\Users\eduar\Desktop\Учеба\sait_na_Laravel`

1. **Запуск локального сервера**:
   ```powershell
   php artisan serve --port=8000
   ```
   Сайт открывается по адресу: **`http://127.0.0.1:8000`**

2. **Запуск автоматических тестов**:
   ```powershell
   php artisan test
   ```
   *(Тесты используют `:memory:` SQLite и не затирают рабочую базу).*

3. **Сброс и повторный сидинг БД** (при необходимости):
   ```powershell
   php artisan migrate:fresh --seed
   ```

4. **Форматирование кода по стандартам Laravel**:
   ```powershell
   vendor/bin/pint
   ```

5. **Синхронизация с Git**:
   ```powershell
   git add .
   git commit -m "Описание изменений"
   git push origin main
   ```

## 7. Важные правила для Агента

1. **Не усложнять**: помнить, что проект студенческий. Не устанавливать внешние npm-пакеты, Tailwind CLI или Vue/React без прямого запроса пользователя.
2. **Не трогать Playwright MCP без согласования**: в соседних сессиях пользователя может параллельно работать Playwright, избегать конфликтов портов и браузера.
3. **Чистота репозитория**: не создавать мусорных `.md` файлов и временных отчетов в рабочей папке; единственным файлом контекста является этот `AGENT.md`.
4. **Всегда проверять тесты**: перед любым пушем в репозиторий выполнять `php artisan test` (все 9 тестов должны быть зелёными).
